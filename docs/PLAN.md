# Calo — план работ

Каждый этап заканчивается рабочей версией, которой можно пользоваться на телефоне.
Оценки — для одного разработчика вместе с Claude Code.

## Этап 0. Каркас — 1–2 дня ✅

**0.1 Репозиторий (локально).** `git init`, приватный репозиторий на GitHub,
Next.js + TypeScript + Tailwind, ESLint, Vitest, `.env.example`.

**0.2 Стиль.** Шрифты Unbounded / Manrope / JetBrains Mono, дизайн-токены,
компоненты BottomSheet, BigNumber, CheckList, Button. Статичный экран «Сегодня»
и лист «Неделя позади» на тестовых данных — сверка со скриншотом.

**0.3 PWA.** manifest, иконки, `apple-touch-icon`, meta для полноэкранного режима
iOS, service worker (Serwist) — кэш оболочки приложения.

**0.4 База.** `docker-compose.dev.yml` с Postgres для локальной разработки,
Drizzle-схема (§4, с `owner_id` и историей цели и веса), первая миграция, сиды.

**0.5 Вход.** Better Auth: passkey (Face ID) + ссылка на email через SMTP,
allowlist из одного email, API принимает cookie и Bearer-токен.

**0.6 Сервер** — отдельный VPS в Нидерландах (1 vCPU 3,3 ГГц, 1 ГБ RAM, 15 ГБ диск).
Там же работают запросы к Claude API. Бюджет памяти:

| Что | RAM |
|---|---|
| Ubuntu + Docker | ~250 МБ |
| `calc-web` (Next.js standalone, `--max-old-space-size=256`) | 150–250 МБ, лимит 384 МБ |
| `calc-db` (Postgres 17: `shared_buffers=64MB`, `max_connections=20`) | 80–150 МБ, лимит 256 МБ |
| Caddy | ~25 МБ |
| **Итого** | **~500–650 МБ** + swap 2 ГБ на случай пиков |

Правила для маленькой машины:
- Ничего не собираем на сервере: образ собирает GitHub Actions → GHCR,
  сервер делает `docker compose pull && up -d`.
- Тяжёлые разовые задачи (импорт USDA, перевод справочника) — локально,
  на сервер заливается готовый дамп.
- Логи Docker с ротацией (`max-size 10m`, `max-file 3`), `docker image prune`
  после деплоя, ufw: открыты только 22, 80, 443; вход по SSH только по ключу.
- Диск: система ~4 ГБ, образы ~0,7 ГБ, база < 0,3 ГБ, фото ~0,4 ГБ в год
  (сжатие на клиенте до ~200 КБ), бэкапы 14 дней — запас больше 8 ГБ.

Состав: `deploy/vps/compose.yaml` (`calc-web`, `calc-db`, `caddy`), `Caddyfile`
(`calc.egor.am { reverse_proxy calc-web:3000 }`), `deploy.sh` (pull → бэкап →
миграции → up → healthcheck), `backup.sh` (`pg_dump` + фото, 14 дней, копия за
пределы сервера), `bootstrap.sh` (разовая настройка: пользователь `deploy`,
Docker, swap, ufw).

**0.7 Проверка.** На iPhone: `https://calc.egor.am` → «На экран Домой» → вход по
Face ID → экран «Сегодня» в стиле скриншота. Перезагрузка сервера не теряет данные,
тестовое восстановление из бэкапа работает.

## Этап 1. База продуктов — 2 дня ✅
- `scripts/import-usda.ts`: загрузка Foundation + SR Legacy, маппинг нутриентов
  в наш вектор.
- `scripts/translate-foods.ts`: русские названия и алиасы (разово через Claude),
  ручная проверка топ-300.
- Поиск: `pg_trgm` + полнотекстовый поиск, `/api/foods/search`.
- Клиент Open Food Facts (поиск по названию и штрихкоду) с кэшированием в `foods`.

**Готово, когда:** «сливки 20», «пармезан», «rummo» находят верные продукты.

## Этап 2. Дневник MVP — 2–3 дня ✅
- `domain/nutrients.ts` + тесты.
- Способ «Продукт»: поиск → граммы/штуки → запись со снимком нутриентов.
- Экран «Сегодня»: итог ккал, Б/Ж/У, список по приёмам пищи, удаление/правка.
- Навигация по дням.

**Готово, когда:** можно вести дневник за день вручную. ← **здесь уже можно пользоваться**

## Этап 3. Онбординг, цель и нормы — 2 дня ✅
- `domain/norms.ts`: Миффлин — Сан Жеор, поправка на цель и темп, нижний порог
  калорий, белок г/кг по цели, таблица витаминов и минералов
  МР 2.3.1.0253-21 + тесты.
- Онбординг из 4 шагов: цель и темп → пол и год рождения → рост и вес →
  активность → экран «Ваша норма».
- Настройки: смена цели и параметров, ввод веса, график веса, ручная правка норм.
- «норма 2 450» на экране «Сегодня», экран «Нутриенты» с % нормы.

## Этап 4. Мои блюда и рецепты — 2 дня ✅
- `domain/recipe.ts`: сумма ингредиентов, выход готового блюда, порции + тесты.
- Редактор рецепта (ингредиенты из поиска), шаблоны с фиксированным КБЖУ.
- Способ «Мои блюда»: сортировка по частоте и времени суток, добавление в одно касание.
- «Сохранить как блюдо» из любой записи.

## Этап 5. Недельный разбор — 2 дня ✅
- `domain/aggregates.ts`: неделя, прошлая, позапрошлая.
- `domain/rules/`: правила «Что получилось», «На что посмотреть», «Чем добрать»,
  таблица источников нутриентов, защита от нехватки данных. Тест на каждое правило.
- Экран «Неделя» точно по скриншоту + график ккал по дням.
- Показ листа при первом открытии в понедельник, кэш в `weekly_reports`.

**Готово, когда:** на данных тестовой недели экран совпадает со скриншотом.

> **Этапы 6–7 отложены (29.09.2026).** ИИ — Gemini API (бесплатный уровень, ключ
> уже в `/opt/calc/.env`, Google его принимает). Но Google геолоцирует IP сервера
> calc (Timeweb, Амстердам, 72.56.93.77 и IPv6) как Россию — YouTube отдаёт
> `"GL":"RU"` — и Gemini отвечает «User location is not supported». Для всех
> остальных баз адрес нидерландский. Варианты, когда вернёмся: перенести сервер
> к провайдеру с корректной геолокацией (Hetzner/DigitalOcean; bootstrap и deploy
> готовы), прокси через Cloudflare Worker, заявка Google на исправление геолокации.
> Claude API не подошёл: подписку нельзя использовать из своего приложения, API платный.

## Итого
MVP (этапы 0–5) — примерно 11 рабочих дней; с ИИ-вводом (6–7) — около 15;
нативная версия и аккаунты — ещё около недели.

## Решено
- Старт с PWA, потом Capacitor + Apple Health + виджеты (архитектура готова, §11).
- Пока один пользователь, схема многопользовательская с первого дня (§12).
- Цель и параметры тела задаются в онбординге и меняются в настройках (§4а).
